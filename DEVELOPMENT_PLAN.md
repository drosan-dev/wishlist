# План разработки вишлиста

## Цель

Сделать личный вишлист, который помогает выбрать осмысленный подарок, не превращая список в инструкцию. Публичная часть размещается на GitHub Pages; общий статус подарков и анонимные сообщения обслуживает отдельный небольшой API.

## Пользовательские сценарии

1. Посетитель понимает идею списка и переходит к пожеланиям.
2. Смотрит карточки, подсказки и примерную стоимость.
3. Анонимно бронирует подарок; другие видят только статус «кто-то уже выбрал».
4. Сохраняет секретный код и при необходимости отменяет бронь.
5. Читает список нежелательных подарков.
6. Задаёт анонимный вопрос и по коду позже проверяет ответ.

## Архитектура

- Статический интерфейс: React/Vinext, экспорт для GitHub Pages.
- Общие данные: Cloudflare Worker + D1.
- Защита: атомарное резервирование, хеш секретного кода, точный CORS-домен, Turnstile/honeypot и rate limit для сообщений.
- GitHub Actions: сборка и публикация каталога статического экспорта в Pages.
- Никаких приватных ключей в браузере или репозитории.

### 1. Основа — начато

- [x] Информационная архитектура и русский контент.
- [x] Визуальное направление и адаптивный первый экран.
- [x] Локальный сервер разработки.

### 2. Публичные разделы

- [ ] Карточки желаний, категории и фильтры.
- [ ] Полный раздел «Что лучше не дарить».
- [ ] Состояния: свободно, бронируется, забронировано, конфликт и ошибка сети.
- [ ] Диалоги бронирования, отмены и анонимного вопроса.

### 3. Общий backend

- [ ] Таблицы `gifts`, `reservations`, `anonymous_messages` и `message_replies`.
- [ ] API чтения статусов, атомарной брони и отмены по секретному коду.
- [ ] API отправки вопроса и проверки ответа по коду.
- [ ] Антиспам, лимиты и политика хранения данных.

### 4. Публикация

- [ ] Переключить frontend на статический экспорт с корректным `basePath` репозитория.
- [ ] Добавить workflow GitHub Pages.
- [ ] Подключить URL Worker через публичную переменную окружения.
- [ ] Настроить репозиторий и выполнить первую публикацию.

### 5. Приёмка

- [ ] Два параллельных запроса не могут забронировать один подарок.
- [ ] После перезагрузки статусы совпадают у разных посетителей.
- [ ] Полная клавиатурная навигация, видимый фокус и корректные `aria-live` состояния.
- [ ] Проверка 320, 360, 768, 1024 и 1440 px.
- [ ] Контент читается без JavaScript; внешние ссылки безопасны.

## Нужные данные от владельца перед завершением

- Список желаний: название, пояснение, ссылка, ориентир цены, варианты и изображение.

- Cloudflare-аккаунт для Worker/D1 и выбранный способ получения уведомлений.
- Решение: должен ли владелец сайта видеть, какой именно подарок забронирован, или сюрприз нужно скрыть и от него.
